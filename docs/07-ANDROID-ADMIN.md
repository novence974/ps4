# تطبيق الإدارة على Android (مشروع Sketchware Pro)

تطبيق لإدارة المكتبة من الهاتف. يغطي كل أقسام لوحة التحكم في الموقع، ويتصل بالخادم نفسه عبر `/api/v1`.

## ما الذي ستجده

| الملف | الوصف |
|---|---|
| `clients/android-admin/sketchware/UPSL_Admin_v1.0.0.swb` | مشروع Sketchware Pro جاهز للاستيراد |
| `clients/android-admin/build/upsl-admin-1.0.0-test.apk` | نسخة تجريبية للتثبيت المباشر، موقعة بمفتاح اختبار (انظر «ما الذي اختُبر») |
| `clients/android-admin/java/` و`res/` و`assets/` و`icon/` و`project.json` | المصدر نفسه الموجود داخل الـ SWB |
| `clients/android-admin/tools/` | سكربتات توليد الـ SWB وفحصه وبنائه محلياً |
| `clients/android-admin/tests/` | اختبارات الشبكة والرفع على JVM، واختبار الشاشات في Robolectric |
| `clients/android-admin/screenshots/` | لقطات من اختبار الشاشات |

## المتطلبات

- **Sketchware Pro** الإصدار 7.0 أو أحدث، فهو يدعم ملفات Java المخصصة وحقن AndroidManifest والموارد الإضافية. تطبيق Sketchware الأصلي القديم لا يدعمها.
- هاتف بنظام **Android 5.0 (API 21)** أو أحدث لتشغيل التطبيق.
- خادم المكتبة بعد المرحلة الأولى، مع تفعيل واجهة API (الإعدادات ← واجهة API).
- حساب له صلاحية `admin.access`. تظهر للحساب الأقسام المسموحة لدوره فقط، والخادم يتحقق من الصلاحية في كل طلب.
- يُفضَّل أن يعمل الخادم على **HTTPS**. التطبيق يقبل `http://` للاختبار على الشبكة المحلية فقط، بعد تحذير صريح وتأكيد منك.

## الاستيراد في Sketchware Pro

1. انسخ `UPSL_Admin_v1.0.0.swb` إلى الهاتف.
2. افتح Sketchware Pro، ثم من قائمة المشاريع اختر **استعادة نسخة احتياطية (Restore backup)**، واختر الملف.
3. سيظهر مشروع باسم **UPSL Admin** والحزمة `com.upsl.admin`.
4. افتح المشروع ثم اختر **Run** للتجربة. للنشر استخدم **Export/Sign APK** بمفتاحك الخاص.

### أين يوجد الكود

لا يعتمد المشروع على المحرر المرئي ولا على البلوكات. الواجهة مبنية بالكود، ولذلك تجد الشاشات فارغة في المحرر المرئي، وهذا متوقع.

| في Sketchware Pro | المحتوى |
|---|---|
| **Java Manager** (`files/java`) | 43 ملفاً: 27 شاشة (`*Activity.java`) وخدمة الرفع وأدوات الواجهة والشبكة |
| **Resource Manager** (`files/resource`) | 122 أيقونة متجهة (Lucide)، والشعار، وثيم `UpslTheme`، وقواعد استبعاد النسخ الاحتياطي |
| **Assets Manager** (`files/assets`) | خط Readex Pro بوزنين، ونص تراخيص المكونات |
| **AndroidManifest Manager** | ثيم الشاشات، ودعم RTL، و`configChanges`، وخدمة الرفع `TransferService` من نوع `dataSync` |
| **Permission Manager** | الإنترنت، وحالة الشبكة، وإبقاء الجهاز نشطاً أثناء الرفع، وخدمة المقدمة، والإشعارات |

ملف كل شاشة في `files/java` يحل محل الملف الذي يولده Sketchware لها. لذلك:

- **لا تغيّر أسماء الشاشات** الـ27 (`main` و`dashboard` و`games` …) ولا تحذف أياً منها.
- **أبقِ AppCompat معطلاً**، فالتطبيق مبني على مكونات Android الأساسية دون مكتبات إضافية.
- لا تضف بلوكات لهذه الشاشات، لأنها لن تُستخدم مع وجود ملف Java المخصص.

## أول تشغيل

1. اكتب رابط الموقع (مثل `https://library.example.com`) واسم المستخدم وكلمة المرور.
2. يتحقق التطبيق من `/api/v1/status` ثم يسجّل الدخول. لا تُحفظ كلمة المرور. يُحفظ رمز دخول باسم الجهاز، مشفراً بمفتاح AES من **Android Keystore** على Android 6 فأحدث، ومستبعداً من النسخ الاحتياطي السحابي.
3. يمكنك إلغاء رمز هذا الجهاز من «حسابي ← أجهزتي»، أو من «رموز API» في الموقع.
4. إذا أُلغي الرمز أو انتهت صلاحيته يعود التطبيق إلى شاشة الدخول تلقائياً.

## رفع الملفات الكبيرة

- يُرفع الملف على أجزاء بالحجم الذي يحدده الخادم (5MB افتراضياً). يُرسل مع كل جزء بصمة SHA-256 خاصة به، ثم تُرسل بصمة الملف كاملاً عند الإكمال.
- يعمل الرفع داخل **خدمة في المقدمة** مع إشعار تقدم، فيستمر حتى لو أغلقت الشاشة.
- **Android 13+** يطلب إذن الإشعارات عند أول رفع. إن رفضته يستمر الرفع دون إشعار.
- إذا انقطع الاتصال يتوقف الرفع ويمكنك استئنافه. يعيد الخادم قائمة الأجزاء المستلمة، فيكمل التطبيق من حيث توقف ولا يعيد إرسالها.
- الملفات الأكبر من «تجميع مباشر حتى (MB)» يجمعها طابور الخادم. ينتظر التطبيق النتيجة، ويشغّل الطابور بنفسه إن لم يكن عامل الطابور أو cron يعمل.
- الامتدادات المسموحة يحددها المدير في «الإعدادات ← الأمان والرفع». الامتدادات الخطرة مرفوضة دائماً.

## الأمان

- كل طلب يحمل `Authorization: Bearer`، والخادم يتحقق من صلاحية كل عملية مهما أظهرت الواجهة.
- الحذف والإيقاف والاستعادة والإجراءات الجماعية تطلب تأكيداً. استعادة نسخة احتياطية تطلب كلمة مرور الحساب، ويُنشئ الخادم نسخة أمان من الوضع الحالي قبلها.
- لا تُسجَّل كلمات المرور ولا الرموز في السجلات. قيم الإعدادات السرية (مثل كلمة مرور SMTP) لا يعيدها الخادم أبداً.
- **على Android 5.x** لا يتيح النظام مفاتيح Keystore للتشفير. هناك يُحفظ الرمز في التخزين الخاص بالتطبيق فقط. ألغِ رمز أي جهاز تفقده.

## ما الذي اختُبر (وما الذي لم يُختبر)

| الاختبار | النتيجة |
|---|---|
| ترجمة كل الكود بـ ECJ بمستوى Java 1.7 على android.jar الإصدار 34، وهو ما يستخدمه Sketchware Pro افتراضياً | ✓ بلا أخطاء |
| فحص الـ SWB: كل ملف مشفر يُفك بمفتاح Sketchware ويُحلل بصيغته، ثم استعادته كما يفعل `BackupFactory.restore()` وبناء APK من الملفات المستعادة وحدها (aapt2 ← ECJ ← D8 ← توقيع) | ✓ |
| نواة الشبكة على JVM (ملفات `Api` و`Session` و`Transfers` نفسها) ضد خادم حي على nginx وApache: الدخول، والأخطاء وحقولها، والتكرار، ورفع الصور، والرفع المجزأ بأحجام 12 و18 و31MB مع الإيقاف والاستئناف والإلغاء والامتداد الممنوع والتجميع عبر الطابور، والتحقق من الملفات، والإجراءات الجماعية، والنسخ الاحتياطي، والخروج | ✓ ‏37/37 على كل خادم |
| الشاشات الـ27 في Robolectric، أي إطار Android 14 الحقيقي على JVM، ضد الخادم الحي: الدخول وتحذير http، والقوائم، والتبويبات، والنوافذ، والتحقق في النماذج، والرفع عبر مستند `content://`، وإخفاء الأقسام عن دور «مشرف»، و48 لقطة شاشة | ✓ ‏20/20 فحصاً، دون أي استثناء غير معالج |
| **استيراد الـ SWB داخل تطبيق Sketchware Pro نفسه** | ✗ لم يُجرَّب هنا: لا يوجد هاتف أو محاكي في بيئة التطوير |
| **تشغيل التطبيق على هاتف أو محاكي حقيقي** | ✗ لم يُجرَّب. Robolectric يشغّل كود Android الحقيقي لكنه ليس جهازاً؛ مثلاً إشعار خدمة الرفع ومنتقي الملفات وKeystore لم تُختبر على جهاز |

**ملف `upsl-admin-1.0.0-test.apk`** بُني بسكربت محلي يحاكي خطوات بناء Sketchware Pro لهذا المشروع، ولم يُبنَ داخل Sketchware Pro نفسه. هو موقّع بمفتاح اختبار، ومناسب للتجربة المباشرة فقط. للنشر ابنِ من Sketchware Pro بمفتاحك.

نرجو عند تجربتك الأولى إبلاغنا بنتيجة الاستيراد والبناء داخل Sketchware Pro. وإن ظهرت شاشة خطأ (DebugActivity) أرسل النص الظاهر فيها.

## حل المشكلات

| المشكلة | الحل |
|---|---|
| «لم يُعثر على واجهة API على هذا الرابط» | اكتب رابط الموقع الرئيسي فقط دون `/admin` أو `/api`، وتأكد من تفعيل الواجهة في الإعدادات |
| «شهادة HTTPS للخادم غير موثوقة» | ثبّت شهادة صادرة عن جهة معروفة (مثل Let's Encrypt). التطبيق لا يتجاوز فحص الشهادات |
| «طلبات كثيرة خلال وقت قصير» | حد الطلبات في الدقيقة. انتظر قليلاً أو ارفع الحد من «واجهة API» |
| الرفع يتوقف عند «تحقق وتجميع» | فعّل عامل الطابور أو cron (انظر `01-INSTALL.md`)، أو اضغط «تشغيل الطابور الآن» في «حالة النظام» |
| خطأ بناء بعد تعديل في Sketchware | تأكد أنك لم تفعّل AppCompat ولم تغيّر أسماء الشاشات، ثم راجع ملف Java الذي عدلته |

## إعادة توليد الـ SWB من المصدر

```bash
cd clients/android-admin
python3 tools/gen_icons.py ../../server/public/assets/img/icons.svg res/drawable   # الأيقونات (عند تغيير الأيقونات فقط)
python3 tools/make_swb.py sketchware/UPSL_Admin_v1.0.0.swb                        # يحزم java/ و res/ و assets/ في ملف .swb
SKETCHWARE_PRO_SRC=/path/to/Sketchware-Pro \
python3 tools/check_swb.py sketchware/UPSL_Admin_v1.0.0.swb build/test.apk       # يفحص ويستعيد ويبني APK
```

يحتاج `make_swb.py` إلى Python 3 مع `cryptography` فقط. أما الفحص والبناء المحلي فيحتاجان أيضاً إلى `Pillow` وJDK 17 أو أحدث وECJ وAndroid build-tools 34 وandroid.jar 34، وإلى نسخة من مصدر Sketchware Pro (`SKETCHWARE_PRO_SRC`)، لأن البناء يعيد منها توليد الأصناف التي يولّدها Sketchware عادة، مثل `SketchApplication` و`DebugActivity`. هذه الأصناف لا تدخل في الـ SWB.
