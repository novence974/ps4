# دليل ربط التطبيقات بالخادم (Android و PS4)

الخادم جاهز الآن لاستقبال التطبيقين. التطبيقان نفسهما سيُبنيان في المرحلتين الثانية والثالثة. يشرح هذا الدليل ما يحتاجه أي تطبيق للاتصال، وهو المرجع الذي ستُبنى عليه المرحلتان.

## 1. بيانات الربط

من «لوحة التحكم ← إعدادات API ← بيانات الربط للتطبيقات» انسخ ما يلي:
- **عنوان الخادم**، مثل `https://library.example.com`.
- **مسار API**، أي العنوان نفسه مضافاً إليه `/api/v1`.
- **طريقة المصادقة:** `Authorization: Bearer <token>`.
- **حجم جزء الرفع**.

**الشروط:**
- **HTTPS ضروري:**
  - Android 9 وما بعده يمنع اتصالات HTTP غير المشفرة افتراضياً.
  - الرموز وكلمات المرور يجب ألا تمر بلا تشفير.
  - للتجربة على شبكة محلية فقط، يمكن السماح بعنوان الخادم في إعدادات أمان الشبكة للتطبيق.
- **CORS** يخص المتصفحات فقط، ولا تحتاجه التطبيقات الأصلية.
- **رابط الموقع الصحيح:** كل روابط الصور والتنزيل في الاستجابات تُبنى من `app.url` في `config.php`، فيجب أن يكون هو الرابط الذي يصل إليه الجهاز.

## 2. تسلسل الاتصال في أي تطبيق

1. **فحص الخادم:** `GET /api/v1/status`. يجب أن تكون `status = "ok"`. إن كانت `maintenance = true` اعرض رسالة الصيانة.
2. **الدخول:** `POST /api/v1/auth/login` مع `{"login": "...", "password": "...", "device_name": "Android — اسم الجهاز"}`، واحفظ `token` بأمان.
3. **الصلاحيات:** `GET /api/v1/user/profile` يعيد `permissions[]`. يعرض التطبيق أدوات الإدارة فقط لمن يملك صلاحيتها، مثل:
   - `games.create`
   - `files.upload`
   
   والخادم يتحقق مرة أخرى في كل طلب على أي حال.
4. **الرد 401** يعني أن الرمز انتهى (30 يوماً افتراضياً) أو أُلغي من «الأجهزة المتصلة»، فأعد الدخول.
5. **الرد 429** يعني تجاوز حد الطلبات. انتظر عدد الثواني في `Retry-After`.

## 3. تطبيق المدير Android (المرحلة 2، Sketchware Pro)

### المسارات التي سيستخدمها

| الوظيفة | المسارات |
|---|---|
| لوحة سريعة | `GET /admin/stats`، `GET /admin/health` |
| الألعاب | `GET/POST /admin/games`، `GET/PUT/DELETE /admin/games/{id}`، `POST /admin/games/{id}/publish`، `GET /admin/games/check-duplicates` |
| الصور | `POST /admin/games/{id}/cover`، `/banner`، `/screenshots` (multipart) |
| رفع ملفات اللعبة | `POST /admin/uploads/init` ← `/chunk` ← `/complete`، و `GET /admin/uploads/{id}` للاستكمال |
| المستخدمون والتحديثات والإشعارات | `/admin/users`، `/admin/updates`، `/admin/notifications` |

### الرفع من Android

مكوّن RequestNetwork في Sketchware يرسل نصاً أو JSON ولا يرسل بايتات خام، لذلك يقبل الخادم صيغتين للأجزاء:
- **من Sketchware مباشرة:** JSON بالشكل التالي. يزيد الحجم المنقول نحو الثلث بسبب Base64، لكنه يعمل دون كود إضافي:
  ```json
  {"upload_id": "…", "chunk_index": 3, "data_base64": "…"}
  ```
- **بكود Java مضاف داخل Sketchware Pro** (HttpURLConnection): إرسال البايتات الخام مع الترويسات `X-Upload-Id` و `X-Chunk-Index` و `X-Chunk-Sha256`. أسرع وأقل استهلاكاً للذاكرة، وهو المقترح للملفات الكبيرة.

**الاستكمال بعد انقطاع الشبكة أو إغلاق التطبيق:**
1. أعد إرسال `init` بنفس الاسم والحجم.
2. سيرد الخادم بنفس `upload_id`، ومعه `"resumed": true` وقائمة `received`.
3. أرسل الأجزاء الناقصة فقط.

احسب SHA-256 لكل جزء وللملف كاملاً، فالخادم يرفض أي جزء أو ملف لا تطابق بصمته. التفاصيل الكاملة في `03-API.md`، القسم 6.

## 4. تطبيق مكتبة PS4 (المرحلة 3)

### المسارات التي سيستخدمها (قراءة فقط تقريباً)

| الشاشة | المسارات |
|---|---|
| البداية | `GET /status`، `GET /platforms`، `GET /games?featured=1`، `GET /games?sort=newest` |
| التصفح والبحث | `GET /games?platform=&category=&sort=&page=`، `GET /search?q=&suggest=1` |
| تفاصيل اللعبة | `GET /games/{id}` (الوصف، الإصدارات، التوافق، الملفات، `platform_info`) |
| المفضلة والسجل | `GET/POST/DELETE /user/favorites`، `GET /user/history` |
| الإشعارات والتحديثات | `GET /user/notifications`، `GET /updates` |

### صيغ الصور

- استخدم الحقول `sm_jpg` و `md_jpg` للأغلفة و `md_png` للشعارات، لأن مكتبات الصور المتاحة في تطبيقات PS4 المستقلة لا تدعم WebP عادة.
- المقاسات الصغيرة (`sm`) مناسبة للشبكات (نحو 300×450 للغلاف)، و `md` لصفحة التفاصيل.

### التنزيل والتثبيت (حدود صريحة)

- عرض الملفات وروابطها وبصماتها متاح عبر API لكل من يملك الصلاحية.
- **لا تقدم هذه المنظومة أي وظيفة لتثبيت الألعاب على PS4، ولا تتجاوز أي حماية أو توقيع أو إدارة حقوق رقمية.**
  - الأجهزة القياسية تثبّت الحزم الرسمية الموقّعة من المتجر أو القرص فقط.
  - هذه المعلومة معروضة للمستخدم في `platform_info.install_notes`، ويحررها المدير.
- إن أُضيف تنزيل داخل تطبيق PS4 في المرحلة 3، فسيقتصر على الملفات المصرح بها، مثل الأدلة والملفات العامة، وبالبروتوكول نفسه:
  1. طلب رابط موقّع.
  2. التنزيل بطلبات Range.
  3. مطابقة SHA-256.

### التنقل

- كل البيانات مرقّمة بالصفحات (`page` و `per_page`) لتناسب الشبكات البطيئة والتمرير بيد التحكم.
- `ETag` يوفر إعادة تحميل البيانات غير المتغيرة.

## 5. اختبار الربط قبل بناء التطبيقات

من أي جهاز على نفس الشبكة أو من الإنترنت:

```bash
curl -s https://library.example.com/api/v1/status
curl -s -X POST https://library.example.com/api/v1/auth/login -H 'Content-Type: application/json' \
     -d '{"login":"admin","password":"…","device_name":"اختبار"}'
```

أو استورد `docs/postman_collection.json` في Postman، واضبط المتغيرات `base` و `login` و `password`، ثم شغّل طلب «Login». يُحفظ الرمز تلقائياً لبقية الطلبات.

**أسباب الفشل الشائعة:**

| العَرَض | السبب |
|---|---|
| الاتصال يُرفض من Android | الخادم بلا HTTPS أو بشهادة غير موثوقة |
| روابط الصور تشير إلى `localhost` | `app.url` في `config.php` غير صحيح |
| الرد 401 رغم إرسال الرمز على Apache | ترويسة `Authorization` لا تصل إلى PHP. راجع دليل التثبيت، القسم 5 |
