جرت كل الاختبارات في 2026-11-25 على تثبيت نظيف بالبيانات التجريبية، فوق خوادم حقيقية:

| العنصر | الإصدار أو المواصفة |
|---|---|
| نظام التشغيل | Ubuntu 24.04 |
| PHP | 8.3.6 (FPM مع OPcache) |
| قاعدة البيانات | MariaDB 10.11 بوضع SQL الصارم المطابق لـ MySQL 8 (`ONLY_FULL_GROUP_BY` و `STRICT_TRANS_TABLES`…) |
| الكاش | Redis 7 |
| خوادم الويب | nginx 1.24 و Apache 2.4.58 |

التقارير الآلية الخام في `docs/reports/`:
- `api-tests.json`
- `browser-e2e.json`
- `perf.json`

## طريقة التشغيل

كل الاختبارات تُنشئ بياناتها الخاصة (بأسماء تبدأ بـ `zz-test` أو `zz-e2e` أو `PERF-`) وتحذفها في النهاية. يمكن تشغيلها على خادم حقيقي دون أن تترك أثراً.

```bash
cd server
# 1) API والأمان والرفع والتنزيل وصفحات الموقع (على جهاز الخادم نفسه)
php tests/run.php --base=https://موقعك --admin=admin --admin-pass='…' [--filter=الأمان] [--report=../docs/reports/api-tests.json]

# 2) الأداء: يضيف 5000 لعبة مؤقتة ثم يحذفها
php tests/perf.php --base=https://موقعك --games=5000 --requests=400 --concurrency=16

# 3) المتصفح الحقيقي (يحتاج Node 18+ و Chrome)
cd tests/e2e && npm install
node browser-e2e.js --base=https://موقعك --admin=admin --pass='…' --chrome=/usr/bin/google-chrome --shots=../../docs/screenshots
```

اختبارات الأمان العشرون تتحقق مما يلي:
- **صلاحيات المسارات:** الزائر يأخذ 401 والمستخدم 403 على مسارات الإدارة. المشرف لا يحذف ولا يدير المستخدمين.
- **منع تصعيد الصلاحيات:** لا يمنح المدير دور المدير الرئيسي، ولا يعدّل أصحابه، ولا يرقّي نفسه.
- **الإسناد الجماعي:** إرسال `role_id` أو `username` في تعديل الملف الشخصي لا يغيّرهما.
- **الحسابات والوصول:**
  - الحساب الموقوف يفقد الوصول فوراً.
  - منع الوصول إلى رموز مستخدم آخر (IDOR).
- **روابط التنزيل:** أي عبث بالرابط الموقّع يُرفض، سواء تغيّر رقم الملف أو مُدّد وقت الانتهاء أو انتهت صلاحيته.
- **CSRF:** النماذج، وطلبات API التي تستخدم كعكة الجلسة.
- **XSS:** الحمولة تُعرض مهرّبة، و CSP صارمة بنظام nonce وبدون `unsafe-inline` أو `unsafe-eval`.
- **حقن SQL:** في البحث والفلاتر والترتيب، دون توسيع للنتائج ولا تسريب ولا ضرر بالجداول.
- **رفع الملفات:**
  - رفض 7 أسماء ملفات تنفيذية أو مزدوجة الامتداد.
  - رفض PHP متنكر بصورة.
  - حذف شيفرة ملحقة بصورة PNG بإعادة الترميز.
  - الرد 413 على الحجم الزائد.
- **المجلدات المحمية:**
  - لا تنفيذ لأي PHP داخل `/media`.
  - لا وصول إلى `config` أو `storage` أو `app` أو `.env` ولا عبور مسارات.
- **الترويسات:**
  - ترويسات الأمان، وإخفاء `X-Powered-By`.
  - كلمات المرور بـ Argon2id، والرموز تُخزّن كبصمات SHA-256 فقط.
- **الاستعادة والحدود:**
  - استعادة كلمة المرور لا تكشف وجود البريد.
  - حد الطلبات العام يرد 429 مع `Retry-After`.
  - حماية الدخول من التخمين حسب العنوان.

**كيف تُقرأ هذه الأرقام:**
- الاختبار يبدأ بكاش فارغ، فأبطأ القيم (p99) هي أول الطلبات قبل امتلاء الكاش.
- البحث الواحد بدون كاش يستغرق نحو 16 ms على الخادم. ارتفاع الرقم إلى ~100 ms سببه 16 طلباً متزامناً على نواتين فقط.
- استعلام القائمة الرئيسي يستخدم الفهرس `idx_games_pub_created` دون فرز في الذاكرة.

**تحسينات أدخلها اختبار الأداء نفسه:**
- **البحث:** كان يُنفَّذ كاستعلام فرعي تابع لكل صف، وكان p50 تحت الحمل 628 ms. صار جدولاً مشتقاً يُحسب مرة واحدة مع العد في الاستعلام نفسه، فأصبح أسرع بنحو 6 مرات.
- **القوائم:** صارت تُرتَّب وتُقسَّم على المعرّفات فقط، ثم تُجلب الصفوف الكاملة للصفحة المطلوبة. تضاعف عدد طلبات القائمة في الثانية تقريباً، وانخفض حساب قوائم الرئيسية بلا كاش من 63 ms إلى 23 ms.

## 5. أخطاء كشفتها الاختبارات وأُصلحت

الاختبار الفعلي كشف أخطاء حقيقية لم تكن ظاهرة في المراجعة البصرية، وكلها أُصلحت وأعيد اختبارها:

1. **صفحات إدارية تتعطل بالكامل** (الأجهزة، والتصنيفات، والمستخدمون، والأدوار، والتحديثات، والإشعارات): تعارض اسم دالة مع الصنف الأب أدى إلى خطأ فادح.
2. **أي نموذج ويب ببيانات خاطئة يعيد خطأ 500 بدل رسالة التحقق**، ومن ذلك الدخول بكلمة مرور خاطئة: استدعاء `reset()` على خاصية للقراءة فقط.
3. **استعلام حالة الرفع وإلغاؤه يعيدان 404**، فلم يكن زر «استكمال» يعرف ما رُفع: موجّه المسارات لم يقبل الأقواس المتداخلة في القيود.
4. **استعلامات لا تعمل على MySQL 8** بسبب `ONLY_FULL_GROUP_BY`. أُعيدت كتابتها، وصار التطبيق يفرض الوضع الصارم في كل اتصال ليتطابق السلوك على كل الخوادم.
5. **بطء البحث** تحت الحمل (انظر قسم الأداء).
6. **الرفع والتنزيل لا يتفاعلان فوراً مع انقطاع الشبكة**. أضيفت مراقبة حدث `offline` ومهلة توقف 45 ثانية.
7. **خيار «بدون بيانات تجريبية» في معالج الويب لم يكن يعمل**.
8. **مجلدات فارغة تبقى بعد حذف الألعاب**، و**أجزاء رفع تبقى لألعاب محذوفة**.
9. **تثبيتان على خادم Redis واحد كانا يتشاركان مفاتيح الكاش**. صار لكل تثبيت بادئة فريدة. وكاش APCu لم يعد يُختار تلقائياً لأن أدوات سطر الأوامر لا تستطيع مسحه.
10. **رسائل Apache:** صيغة `Deny from all` القديمة استُبدلت بصيغة متوافقة مع Apache 2.4.
11. **أخطاء في الواجهة:**
    - الأرقام في شريط التقدم كانت تظهر معكوسة في الواجهة العربية.
    - سهم القوائم المنسدلة كان يختفي في الوضع الفاتح.
    - صيغة الجمع العربية كانت خاطئة («5 لعبة» صارت «5 ألعاب»).

## 8. حدود معروفة

- **Apache بدون mod_xsendfile:** عند تمرير الملفات عبر PHP-FPM يحذف Apache ترويسة `Content-Length` (لوحظ حتى مع سكربت من سطرين). التنزيل والاستكمال يعملان، لكن الحجم لا يظهر مسبقاً في مدير تنزيلات المتصفح. الحل المختبر: X-Sendfile (دليل التثبيت، القسم 5). وفي nginx لا توجد هذه المشكلة.
- **ما لم يُختبر في هذه البيئة:**
  - الإرسال عبر خادم SMTP حقيقي. اختُبر البريد عبر سجل الملفات، ويتطابق محتواه مع ما يرسله SMTP.
  - كاش APCu.
  - PHP 8.2 (اختُبر 8.3 فقط، ولا يستخدم الكود ميزات خاصة بـ 8.3).
  - MySQL 8 الأصلي: اختُبر MariaDB بوضع MySQL 8 الصارم.
- **أرقام الأداء** تخص خادماً بنواتين. على خادم إنتاج أقوى تكون أفضل، وعلى استضافة مشتركة قد تكون أبطأ.
